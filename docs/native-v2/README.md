# iOS v2 全原生迁移

2026-11-19 启动。长期目标为把 MoviePilot iOS 主体的全部功能迁移到原生 UI，直接对接 MoviePilot 后端；保留现有插件生态，既有 Web 插件仍可使用插件专用 WebView。

**当前是独立 v2 开发分支，尚不是可替换 1.x 的完成版本。** 原有客户端暂留作功能和行为对照，不能据此宣称 v2 已去除 WebView。总目标和当前叶子的事实以路线图及验收记录为准。

## 原则

1. 按功能闭环迁移：列表、详情、编辑、确认、失败恢复、权限和系统入口一起验收；不能只做静态外观。
2. 主体原生与插件兼容分开计量。JSON 原生渲染、Web 插件兼容分别记录，兼容回退不能充当“原生完成”。
3. 先建立接口与状态归属，再定稿主要页面视觉，随后逐个交付功能。已有实例、登录和插件不要求用户重建。
4. 不维护另一套后端业务规则。主机、权限、状态和实际执行结果以现有 MoviePilot API 为准。
5. 文档随代码更新；每项完成都要能跳转到代码、测试和证据。未验证和不可验证的情况明确保留。

## 范围核对

基线读取已 fetch 的固定 Git 对象，不使用前端、后端和插件仓其它任务的未提交改动。当前静态统计为 35 个路由入口、33 个页面文件、90 个通用业务弹窗、8 个设置视图、221 个组件文件，以及后端端点目录内 467 个静态操作声明。

这些数字用来避免漏项，**不等于 467 个已挂载或本 App 都需要消费的 API，更不是迁移完成率**。运行时注册、继承、辅助文件生成的 JSON 以及第三方插件需要补充独立夹具。

重新生成清单需先按工作区流程获取相关目标分支，再运行：

~~~sh
# App 仓无 Python 环境时，使用工作区已记录的 MoviePilot 仓环境，仅作标准库静态扫描。
/Users/jxxghp/MPProjects/MoviePilot/.venv/bin/python \
  -W ignore::SyntaxWarning scripts/native-v2-inventory.py \
  --as-of 2026-11-19 --output docs/native-v2/baseline.json
~~~

重放旧基线时将四个 --*-ref 参数分别设为 baseline.json 中的完整 SHA。更新清单不能自动把新增能力标成已实现；变化必须进入范围矩阵与路线图。
