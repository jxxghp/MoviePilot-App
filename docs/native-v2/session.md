## 身份与认证

- 使用强类型用户 ID、名称、头像、等级、权限和激活状态，不通过 browserStorage、网页 Pinia Store 或 BridgeError 表达原生身份。
- 普通用户分类默认值与现有客户端一致：discovery/search/subscribe 为 true，manage 为 false；features 缺省继承，明确 false 禁用。permissions.admin 不能将普通账号变为管理员，管理员只认 is_superuser。
- login/access-token 仍发送独立编码的 username/password/otp_password 表单；只在用户明确提交时发送一次。401 的 X-MFA-Required 与可用方法原样保留，不因多方法挑战而假装认证成功。
- user/current 验证保存的令牌后才可恢复；不能从 JWT 中自行授予用户/权限。仅在令牌已被 current 验证后，可沿用其 level 作为既有展示等级的回退。
- login/initialization 保留 initialized/configured_username；404 仅表示旧实例无该探测接口，不视为需要创建管理员。
- 认证传输只开放固定路径；使用私有临时 URLSession、无全局 Cookie/缓存/凭据、流式大小上限、禁止自动重定向与重发。普通 JSON 业务请求仍使用 MoviePilotAPI。
- 密码/OTP 不进入任何模型、日志或持久化。认证结果仅在模块内部访问令牌，对外描述与 debug 输出隐藏令牌。

## 会话状态与任务归属

实例继续使用现有 SavedInstance 的 UUID 与 ServerAddress，不重新生成身份或改变 Keychain service/account。一个成功会话包含 instanceID + userID + 不重复 generation；同一实例重新登录也形成新代次。

每次选择实例或明确登录都先销毁旧会话、取消旧认证客户端；成功响应在交付及持久化前再次核对当前尝试和实例。即使底层任务忽略取消，迟到响应也不能保存令牌、授予身份或覆盖新实例状态。

会话发起的 API 在请求前和返回后检查存活/权限。401 只让产生该响应的当前会话过期，403 作为无权操作返回；旧会话的迟到 401 不能清除新账号令牌。确认框之后必须使用仍有效的会话再次检查权限。

状态区分：未连接、正在恢复、需要登录、正在登录、已认证、连接/存储失败。取消不是用户名密码错误；离线不删除仍有效的保存令牌；网络失败不回退其它会话的旧数据。

## 保持登录与失败处理

当前 TokenStore 保持 org.moviepilot.authentication.v1 / 实例 UUID / 本机不可同步 Keychain 语义，原生会话只通过小型存储协议使用它，不复制第二套令牌库。

新身份验证成功后，先核对仍为当前尝试，再处理该实例旧令牌。关闭保持登录必须真实移除旧令牌；保留登录则清理旧记录后保存新令牌。无法清理或保存时明确失败，不让 B 账号进入活动会话但背后仍保持 A 的自动登录。

恢复失败为 401 时只清理匹配尝试的实例；普通网络失败和 403 不冒充令牌撤销。注销先使内存/API 会话立即失效，再处理当前实例的保存令牌；清理失败必须可见。其它实例与单独选择保存的密码不顺带删除。

## 本阶段验收

1. 用户/权限默认值、features、管理员、非法身份/类型、等级回退。
2. 正确表单、OTP、多 MFA、初始化/404、原始/包装登录结果、恢复当前权限、HTTP/业务失败。
3. 无 Cookie/缓存继承、同源/跨源重定向拒绝、认证流式上限、取消、不自动重发、令牌不出现在描述中。
4. A→B→A、同实例换用户、忽略取消的迟到响应、退出、401/403、权限变更、存储失败与非保持登录。
5. 现有核心回归、严格格式、iOS 16 SDK 目标编译；修改平台接线后额外验证实际 Xcode App 目标编译。

实际模拟器 UI、真实后端账号、真机、安全认证和 Web 插件仍分别验收；此阶段不代替它们。
