# 视觉方案与设计交付

## 当前已确认方向：Rex 参考（2026-11-19 用户追加）

**以路线图“用户确认的全局视觉约束”为强制接续入口。** 用户否定首次账号页普通系统分组表单的外观，已经给出明确参考：全局渐变、玻璃卡片与表单、海报主导、Apple 原生语言，且点名使用 `swiftui-liquid-glass` 技能。早先的“先在几种视觉间选择”不再适用；首次账号截图只是功能历史。

六张参考已持久化到 [Rex 参考索引](references/rex/README.md)。本批以深蓝紫/烟紫/玫瑰色的连续背景、透底材质、自然海报比例及悬浮系统导航为准，先给出同一体系的原生预览。

| 范畴 | 必须实现/检查 | 不接受的替代 |
| --- | --- | --- |
| 背景 | 根容器统一渐变，贯通安全区、导航、滚动内容、设置与表单；大图与渐变自然融合 | 仅登录页或局部卡片有渐变，其余纯色底 |
| 表面 | 半透明玻璃分组卡片/表单、细边缘高光、统一圆角与间距，保持文字对比度 | 不透明系统白卡/深灰卡，或只加阴影冒充材质 |
| 内容 | 大图主视觉、2:3 海报、横向分区与海报网格；图片清晰、主体完整、标题克制 | 用文字列表、色块、占位框代替参考要求的图像密度 |
| 控件 | 系统字体、SF Symbols、原生返回/搜索/开关/选择器；清晰触控区和状态 | 网页、整页截图、手画状态栏、堆砌无功能的装饰按钮 |
| Liquid Glass | 遵循指定技能；iOS 26+ 采用原生 API，成组玻璃由 GlassEffectContainer 管理，效果位于布局/视觉修饰后，interactive 仅用于可交互控件 | 用自定义模糊替代可用的系统 Liquid Glass，或给每层内容重复叠加重玻璃 |
| 适配 | 同一风格的深浅主题、Dynamic Type、VoiceOver、降低透明度/动态效果和旧系统降级 | 通过缩字、牺牲对比度或删除交互让截图看似符合 |
| 范围 | 登录/连接、主业务、设置、JSON 插件 UI 共用同一套组件；Web 插件外层原生统一 | 完成几个演示页就宣称全局改造完成 |

技能入口：本机 `~/.codex/skills/swiftui-liquid-glass/SKILL.md`，实现前同时读取 `references/liquid-glass.md`，再核对 Apple 当前官方文档。用户原生 SwiftUI 要求优先，不套用网页原型模板。

### 本批交付与视觉验收

1. 先实现隔离的 SwiftUI 原生预览：发现/海报网格、媒体详情、工作台、设置与插件配置表单，媒体内容明确使用演示素材。
2. 共享背景、玻璃表面、控件与排版规则，预览确认后由 P1.4 接入真实主体及动态 JSON 组件。
3. 从模拟器采集真实画面，与对应参考以匹配主题/视口/状态并排对照；检查字体、间距、色彩/透明度、图片与内容五个面。
4. 修正影响视觉或可用性的差异后再展示。保留源图、实现图、对比图、交互与可访问性检查；构建成功不当作设计通过。

## 目标

保留 MoviePilot 的媒体海报、清晰分区、主题主色、卡片、壁纸与玻璃导航风格，改进信息密度和操作层级。主体是真实原生布局，不把网页截图切片做成界面。

参考现有 [推荐](../../screenshots/screens/06.png)、[仪表板](../../screenshots/screens/02.png)、[插件](../../screenshots/screens/07.png)、[订阅](../../screenshots/screens/13.png)、[文件管理](../../screenshots/screens/09.png) 和 [截图册](../../screenshots/README.md)。这些是已有 1.x 视觉参考，不是 v2 实现结果；部分截图来自较早版本，功能仍以本次固定源码为准。

原生导航、内容分层、搜索和可访问性参考：

- [Apple：Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)。
- [Apple：Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)。
- [Apple：Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) 与 [VoiceOver](https://developer.apple.com/design/human-interface-guidelines/voiceover)。

玻璃材质主要服务于导航和悬浮控件；内容区优先保证海报、正文、图表和表单的可读性。旧系统用受支持的系统材质，保持层次一致，不模拟不可用的系统 API。

## 主要页面的预览顺序

| 批次 | 预览 | 先解决的问题 |
| --- | --- | --- |
| D1 | 仪表板、推荐/探索 | 默认首页、导航层级、海报与状态密度、插件卡片位置、iPad 分栏 |
| D2 | 媒体详情、资源搜索、下载确认 | 主操作、季集、来源、筛选和长列表/长文案 |
| D3 | 订阅列表/编辑、下载管理 | 进度与异常、状态筛选、批操作和确认 |
| D4 | 插件列表、JSON 配置、数据页、Web 插件入口 | 原生与兼容的边界、复杂表单、配置/保存/失败反馈 |
| D5 | 文件/工作流/设置/Agent | 高信息密度、节点画布、输入与对话、多任务状态 |

每批展示 iPhone 主画面、关键状态和 iPad 适配示意；不在一张“功能墙”里挤进所有入口。主要页面视觉选定后再批量写页面代码，底层网络/模型/解析器可提前独立实施。

## 方向与默认约束

视觉方向已以用户上传的 Rex 参考为准；保持 MoviePilot 功能语义。页面细节用原生预览评审，不再发散成与参考无关的风格选项。

- iPhone 预览按 390×844pt 布局思考，iPad 按 834×1194pt 思考；实际实现采用 safe area 与自适应布局，不写死设备坐标。
- 正文使用系统动态字体，主操作触控区至少 44pt；不靠缩字容纳复杂表格。
- 最多保留少量稳定的顶级入口；其它能力通过有名称的分类和上下文动作到达。管理员/普通用户的默认入口沿用权限语义。
- 同一个视觉方向必须有浅/深主题，保持既有壁纸/主色偏好；无壁纸时仍有清楚的层级。
- 表单、进度、确认、错误、空态和无权状态要与正常画面同时设计；截图上漂亮但操作闭环缺失不算完成。

最初只查看了既有产品截图，随后交付了账号流程的功能验收画面；用户现已否定那一视觉方向并补充 Rex 六图。不能继续把旧样式当成已认可基线。当前直接制作可审阅的原生预览，图像生成工具不可用不阻塞这批真实 SwiftUI 设计。
