## 新发现与本叶子

核对 VCombobox 的真实生产方时，发现 LibraryIntegrity 的 `page.py` 明确写明 Cron 星期 0 和 7 都表示周日，其 `config.py:92–137` 把标准数字星期改成英文名后才交给 APScheduler。后端通用调度却直接用 APScheduler 3，0 表示周一。故“所有插件的数字星期都按 APScheduler 展示”不是可靠前提，即使手机没有重写原文，也可能误导用户在可视化页里修改执行日。

本叶子先修复已可达的通用 Cron 编辑器，再回到复杂选择：

- 不按插件名称或中文 hint 硬编码方言，也不在 JSON 中擅自添加新必填协议。
- 任何含数字的星期 token（点/列表/范围/步长，包括 7）保留原文并进入原生自定义字段，不把它预选为周一/其它日期；界面明确数字含义由插件决定。
- 通配 `*` 与命名星期仍可可视化；用户明确切换模式并选择星期后才生成 mon–sun 名称。已有原文/类型/空格、完整模型与显式保存边界不变。
- 调整先前错误的 `0 -> .values([0])` 测试假设；新增跨方言值/原样应用/命名生成与独立完整 PUT 断言，不靠删除失败测试降低覆盖。
- 原生界面继续唯一 Cinematic 渐变/玻璃表单，按 swiftui-liquid-glass 复核；新增说明在最大字号/横屏可滚动，不能遮住输入或确认动作。

## 验收与回滚

从固定插件源码只提取完整 Cron 节点及真实 hint，模型明确为合成，不冒充完整 LibraryIntegrity 表单。纯值用例覆盖 0/7、数值列表/范围/步长、命名范围/列表和无改应用。API-only 实操证明打开时没有预选错误日期、无改应用/保存保留原始字符串、明确选周日后保存 sun 且未来字段完整。复测既有命名星期最大字号路径，iPhone/iPad 与既有布局警告/最低系统/真机门禁分别记录。

回滚仅撤销本叶子对数字星期可视化与提示/夹具的变更，不影响通用会话/完整草稿或 Cron 其余字段。完成本地提交后继续 P2.2b.2b，不将完整插件生态或长期 Goal 记为完成。
