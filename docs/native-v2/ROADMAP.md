## 用户确认的全局视觉约束（2026-11-19 追加，后续必读）

用户明确反馈原有设计“太丑”，要求参考 Rex App，并指定使用 `swiftui-liquid-glass` 技能。以下是贯穿 P0.2、P1.4、所有业务页面/JSON 插件 UI 和 P8 总验收的硬要求，不是可选润色：

1. **全局连续渐变背景**：覆盖主体页面、导航/安全区、设置、表单和弹层承载区域；以参考的深蓝紫/烟紫/玫瑰色层次为首轮基准，不能退回大块纯白或纯深灰页面底。
2. **玻璃拟态卡片与表单**：半透明材质透出底色，统一圆角、细分隔、边缘高光和克制层级；按钮、输入、开关、选择器、分组面板保持同一设计体系。不能只把顶部按钮做成玻璃，其余继续沿用旧视觉。
3. **海报主导内容**：发现、详情、订阅/资源列表充分使用真实海报、背景图、横向内容栏和海报网格，保留图像焦点与比例，减少无谓文字/指标堆砌。预览素材与真实后端数据必须区分。
4. **Apple 原生设计语言**：SwiftUI/UIKit、系统字体/SF Symbols、原生导航/返回/搜索/控件、悬浮导航层级及合理的 Liquid Glass；不得用 WebView、HTML/CSS 或整张截图冒充原生 UI。
5. **指定技能**：实现和审阅使用 `swiftui-liquid-glass`，读取其完整 SKILL.md、references/liquid-glass.md，并核对当前 Apple 官方 API。iOS 26+ 原生 glassEffect / GlassEffectContainer / glass 按钮按用途使用；旧系统与减弱透明度/动态效果提供一致、可用的降级。
6. **参考与验收不能丢**：六张原图已保存在 [Rex 参考索引](references/rex/README.md)。每批原生预览/实现需与对应参考在同主题、近似视口/状态下并排对照，检查背景、材质、海报密度、排版、间距、触控和可访问性。
7. **优先级与范围**：这些追加要求覆盖先前普通系统表单的视觉假设，但不取消全功能原生、后端直连、权限/会话隔离和插件生态兼容目标。既有 Web 插件的外层原生容器遵循统一风格，插件内部按兼容协议处理，不能靠强行注入样式破坏插件。
8. **只做一种风格（用户随后明确）**：v2 固定 Rex 参考的深色渐变/玻璃视觉，不做多主题、浅深色方案或主题切换，不再为其它视觉方案分配实施/验收工作。旧版外观记录保留以便回退，不驱动 v2 外观；大字、VoiceOver、提高对比度、降低透明度/动态效果继续验收，它们属于可访问性。

详细规范与验收表见 [design.md](design.md)。这组截图已明确整体方向；先展示发现、详情、工作台、设置/插件表单的同体系原生预览，再批量铺设业务页面，不重新发散成三套无关风格。

## 首批实施顺序

1. P0.1：固定范围、旧架构差异、接口和插件事实，形成本文与配套文档。
2. P1.1：新增与 WebKit 无关的网络模块；验证路径前缀、凭据隔离、响应包装、分页、取消、大小限制与不自动重试。
3. P1.2：复用已有实例/Keychain，建立原生用户、权限、代次与任务归属；去除登录后必须先启动网页的前提。
4. P0.2/P1.4：采用用户已选择的 Rex 唯一风格，展示主要页面原生预览，再把同套组件接入真实页面；不再发散多主题。
5. P2：尽早证明复杂插件可用，避免主体页面迁完才发现生态兼容方案不可行。
6. 每次选下一个满足前置条件的叶子；不为了严格串行阶段编号而空等。

## 当前叶子合同

- 成果：真实 `plugin/form/{physicalID}` 响应经已有限制的原生会话 API 保真解码，完整草稿按原始字段键绑定、保留类型/未知值；具备原生组件覆盖和能力诊断、校验、显式保存与失败保留。
- 拆分：P2.2a 先完成既有受限 API 的原始 Data 接线、物理实例/会话归属、独立草稿与保存门禁；P2.2b 接入 Rex 表单组件、代表真实源码配置和 API-only UI 操作。复杂条件/表达式按已记录语义推进，不能通过删掉这些插件来缩小目标。

### P1.2 原生身份与实例会话

- 成果：WebKit 无关的当前用户与权限模型、实例/用户/代次身份、会话结束与迟到响应保护；认证适配器复用既有后端和 Keychain 归属。

- 暂不包括：主要页面视觉和功能、Passkey/OIDC 完整切换、生产账号写入；后续各自验收。

实施拆分为两个可独立验证的子叶子：

1. P1.2a：纯原生用户/权限、初始化状态、密码/OTP/令牌恢复客户端与协议测试；不接默认 UI，不管理 Keychain。
2. P1.2b：会话代次、失效/取消/迟到响应、实例切换、可选保持登录与现有 Keychain 存储接线；补齐状态机测试和 iOS 编译验证。

子叶子的具体状态归属和失败处理见[会话设计](session.md)。同一时刻仅编辑其中一个；每个通过后先保存聚焦本地提交。

### P1.3 原生启动与交互入口（本地基础验收完成）

- 成果：可运行的 v2 原生启动、实例选择、初始化提示/表单、密码/OTP 登录、恢复、失败/重试/换地址和独立导航入口；完全通过 NativeSessionManager 驱动。
- 修改面：原生 iOS 入口、连接/认证 UI、API-only 回环夹具与 XCTest；保留现有 1.x 默认入口供对照，v2 调试/验收入口不允许回退主体网页。
- 视觉：本叶子的连接/登录截图只作功能历史；P1.4 必须按已记录的 Rex 唯一风格统一，不能把普通系统表单当作已认可方向。主要业务预览不冒充已接后端的完整客户端。
- 验收：真实按钮完成连接→登录→恢复/退出/换实例；夹具不提供前端 HTML/JS；原生入口 WebView 创建数为 0；关键正常/错误画面和请求记录互证。
- 范围：保留既有可选密码记忆和语言入口，不自动提交记住的密码；Passkey/OIDC 等安全认证和插件认证提供方仍单独设计验收。
- 系统集成：本叶子明确会话结束时与现有 Widget/通知等清理接口的归属，不能将默认 UI 切换当作 P7 系统集成已完成。
- 回滚：关闭独立 v2 调试入口即可回到既有默认行为；不删除用户地址簿、Keychain 或真实配置。

实施拆分：P1.3a 补齐初始化 JSON 提交/探测竞态/不自动登录的协议与单元验证；P1.3b 接通原生 UI、API-only 夹具和实际模拟器验收。入口设计见 [entry.md](entry.md)。

## 总目标完成条件

1. coverage.md 所有现有页面、弹窗、全局动作、业务设置与系统入口有对应原生实现和实际验收记录；不能用“已做大部分”关总 Goal。
2. 主体构建及运行链不依赖 WebView、Vue、浏览器持久化、前端桥、前端 index.html 或 JS 资源；缺少这些资源时主体正常工作。
3. 现有 JSON 插件组件族、绑定、条件、事件、数据页和仪表板完成原生验证；既有 Vue/HTML 插件各界面有兼容证据。第三方未知能力有明确诊断和受控插件回退，不默默漏配置或破坏保存。
4. 实例、身份、权限与账号切换正确；用户数据不串用；任务不因迟到响应写回已销毁会话。
5. iPhone/iPad、最低支持系统与当前系统、统一 Rex 外观、大字、VoiceOver、对比度/透明度辅助选项、断网和恢复等适用验收通过；不再以多主题为完成条件，真实设备和后端验收与合成测试分别记录。
6. 可重现的原生候选构建、升级/回滚和设备验收完成；若另获授权公开发布，还须完成对应最终 SHA 的 CI 与发布核验。文档、一次 build 成功、模拟器截图或 IPA 存在均不能单独满足总目标，未请求的公开发布也不成为人为阻塞。
7. P1.3/P1.4 中的系统键盘工具栏相关布局警告需在候选系统矩阵重新核对并处理；独立系统复现证据不能代替产品全部布局/性能验收，不通过关闭诊断或去掉用户功能冒报解决。

## 阻塞与停止条件

- 页面细节待评审：只影响相应页面定稿，Rex 唯一方向已确定；继续模型、契约、插件解析和测试，不把总 Goal 标为 blocked。
- 缺真机/旧系统/生产签名：记录影响的验收门槛，继续其它叶子；不得把模拟器结果写成真机通过。
- 原生与既有插件语义冲突：保留原始配置和状态，产出差异与可回退方案；不通过删字段、关闭权限或禁用插件绕过。
- 未获授权的发布、生产写入或覆盖正式 App：停在该交付门，继续可验证的本地实现。
- 只有不存在任何合规可推进的叶子时才考虑总目标阻塞；主动暂停仅由用户指令触发。
